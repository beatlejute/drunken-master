# interpreter

MCP-сервер, восстанавливающий смысл сообщений с опечатками / ошибками
speech-to-text (см. README.md). В этом репозитории он подключён через
`.mcp.json`, чтобы сценарий можно было проверять вживую.

## Правила для агента в этом проекте

- Если сообщение пользователя выглядит «с телефона» (странные слова,
  несогласованные термины, фонетически похожие на известные), **сначала**
  вызови `interpret_message`, потом действуй.
- Глоссарий собирай сам: название проекта (`interpreter`), имена модулей
  (`pipeline`, `candidates`, `jev`, `server`), термины из README и из
  предыдущих сообщений (`дебаг`, `скилы`, `лисенер`, `Ванневар`, `Jev`,
  `Noul`, `Choice`, `MCP`, `глоссарий`, `коммит`, `деплой`, `тесты`).
- `context` — одна-две фразы о том, что обсуждали; не вставляй туда всю историю.
- `needs_clarification: false` → работай с `variants[0].text` и одной строкой
  сообщи, что исправил.
- `needs_clarification: true` → покажи `format_clarification(...)` и дождись
  ответа пользователя; не угадывай.

## Разработка

```bash
python -m venv .venv && .venv/bin/pip install -e .[dev]
.venv/bin/python -m pytest
.venv/bin/python -m interpreter "текст" --glossary слово1 слово2
```

Вызовы инструмента дописываются в `evals/inbox.jsonl` (см. `INTERPRETER_LOG`
в `.mcp.json`) — из них потом собирается eval-набор.
