Не применяй к чистым сообщениям и к намеренным неологизмам/сленгу.

# Интерпретация искажённого сообщения

Сообщение пользователя может прийти искажённым откуда угодно: голосовой ввод
подменяет слова похожими по звучанию, T9 — частотными, свайп и быстрая печать
дают мусор и склейки, OCR и копипаст ломают буквы. Результат: «Сезонная возможность
что нам придётся косить очень большой соврать» вместо «Есть ли вероятность, что
нам придётся собрать очень большой словарь». Если действовать по такому тексту
буквально, ты сделаешь не то; если молча «примерно понять» — иногда угадаешь
неверно и пользователь этого не увидит. Навык нужен, чтобы восстановление было
явным, проверяемым и — где надо — согласованным с пользователем.

Ты сам — лучший инструмент для этого: у тебя есть контекст разговора, файлы
проекта, знание языка. Внешние спеллчекеры не ловят реальные-но-чужие слова и
ломают жаргон (Yandex Speller: «лиционер → милиционер»). Никаких внешних вызовов
не нужно.

## Шаг 1. Найти подозрительные слова

Пройди по сообщению и отметь слова, которые:
- не согласуются грамматически или по смыслу с соседями;
- похожи по звучанию на термин, имя или слово из контекста разговора;
- не являются словами вообще (свайп-мусор);
- странно уместны — реальное слово, но не из этой темы («обременение» в разговоре
  про тесты).

Если ничего не отметил — сообщение чистое, навык закончен, ничего не говори.

## Шаг 2. Перебрать классы искажений

Для каждого отмеченного слова проверь классы по убыванию частоты:

| Класс | Механизм | Реальные примеры |
| - | - | - |
| ASR подставил реальное чужое слово | похожее звучание, часто другая часть речи | Некто ← Нет; обременение ← общение; задачи ← здесь; строили ← стоило; шаровых ← готовых; соврать ← словарь; Сезонная ← Есть ли |
| Фонетическое искажение термина | термин не в словаре ASR | лиционер ← лисенер; силы ← скилы; Анвар ← Ванневар |
| Разбиение / склейка | ASR разрезал слово на два знакомых | до бага ← дебаг; и есть → иеть |
| Кириллица вместо латиницы | ASR записал англ. термин по-русски | мцп ← MCP; Джейн ← Jev; дебак ← debug |
| T9 / свайп | соседние клавиши, автозамена, мусор | фвлм ← вообще; иеть ← и есть |

Самый частый и самый трудный — первый: слово выглядит нормальным, и заметить его
можно только по несоответствию контексту. Именно поэтому нужен ты, а не словарь.

Для кандидатов используй: имена проектов, модулей, людей, инструментов из
контекста; термины, которые пользователь уже употреблял; то, что *логично сказать*
на этом месте разговора. Проговори искажённое слово вслух (мысленно) — часто
верный вариант слышен: «со-врать» → «сло-варь».

## Шаг 3. Составить прочтения

Собери 1–3 **целостных** прочтения всего сообщения. Меняй только искажённое:
пунктуацию, порядок слов, стиль, мат — не трогай; ты восстанавливаешь, а не
редактируешь. Упорядочь по вероятности и оцени `confidence` каждого так, чтобы
сумма была ≈ 1. Не завышай: если два прочтения одинаково правдоподобны, 0.5/0.5
честнее, чем 0.8/0.2. Ориентир: заменил одно слово с очевидным созвучием — 0.9;
два-три слова, каждое из которых можно услышать иначе — 0.5–0.6, и это повод
спросить, даже если прочтение кажется складным.

**Сверка перед выдачей.** Пройди по оригиналу слово за словом и проверь: каждое
слово либо стоит в прочтении на своём месте, либо есть в твоём списке замен.
Ничего не выброшено, не переставлено, не добавлено. Прочтение — это оригинал с
точечными заменами, а не пересказ. Типичный дрейф: «ты он иеть нахрена тебе
ключ» → «зачем нахрена тебе ключ» (пропали «ты он», «иеть» так и не разобрано);
«подключилась сюда скилл» → «подключила скилл сюда» (переставлено). Если после
сверки в оригинале осталось неразобранное слово — вернись к шагу 2, не сдавайся
на первой найденной замене.

## Шаг 4. Решить: действовать или спросить

Правило без исключений: **если ты мысленно заменил хотя бы одно слово — покажи
это первым, до всего остального.** «Первым» значит буквально: строка «Понял
как: …» — первый текст в твоём ходе, **раньше любого вызова инструмента**.
Не «до текстового ответа» — до действия. Прочитать «Сарат райплайна» как
«старт пайплайна», запустить пайплайн и лишь потом написать «Понял как» — это
нарушение: пользователь узнаёт о твоём прочтении, когда пайплайн уже идёт.
Даже «подключилась → подключила», даже когда смысл очевиден. Молчаливая правка
выглядит как понимание, но пользователь не видит, *что именно* ты понял, и не
может поправить, пока ты не сделал не то. Одна строка ничего не стоит; ошибка,
обнаруженная через три сообщения — или после запуска деплоя, — стоит дорого.

- **confidence топ-прочтения ≥ 0.75** — действуй по нему. Одной строкой покажи,
  как прочитал: «Понял как: …» с выделением замен. Затем действуй и отвечай.
- **Если прочтение ведёт к необратимому или дорогому действию** (аппрув,
  старт пайплайна, деплой, удаление, отправка, оплата) — планка выше: действуй
  без вопроса только при ≥ 0.9 и когда искажённое слово не влияет на *что
  именно* делается. «Апрув плана и Сарат райплайна» → «старт пайплайна» 0.95,
  глагол очевиден — ок. «Удали сборку» с неразобранным словом вместо «сборку» —
  спрашивай, даже если остальное ясно.
- **ниже 0.75** — не угадывай молча. Покажи варианты и дождись ответа:

  ```
  Похоже, в сообщении есть ошибки распознавания. Вы имели в виду:
  1. <прочтение 1>
  2. <прочтение 2>
  3. Ничего из этого
  ```

  Исключение: если все варианты ведут к одному и тому же ответу с твоей стороны
  (расходятся в несущественном слове), скажи «Понял как: …», ответь, и упомяни
  альтернативу одной фразой. Не заставляй пользователя выбирать между тем, что
  для дела неразличимо.

## Шаг 5. Записать (если доступен инструмент `record_interpretation`)

Если в сессии есть MCP-инструмент `record_interpretation`, вызови его сразу с
прочтениями, а после ответа пользователя — ещё раз с `chosen`. Из этих записей
собирается набор для оценки навыка; без них нельзя понять, где он ошибается.
Если инструмента нет — пропусти шаг, навык работает и без него.

## Примеры

**Вход:** «Меня интересует максимальная эффективность я даже не держусь за Джейн»
(контекст: обсуждали модель Jev)
**Выход:** «Понял как: …не держусь за Jev» — 0.95, действуем.

**Вход:** «Некто обременение и тесты теперь будут проводить задачи чтобы не бегать»
(контекст: обсуждали, тестировать здесь или в другой сессии)
**Прочтения:** «Нет, общение и тесты теперь будем проводить здесь, чтобы не
бегать» 0.5; «Общение и тесты теперь будут проводить задачи…» 0.2; исходное 0.3.
**Выход:** нумерованный список — топ ниже 0.75, а прочтения меняют смысл.

**Вход:** «запусти тесты, потом коммит»
**Выход:** ничего — сообщение чистое.

## Чего не делать

- Не «улучшать» текст: если пользователь написал грубо или без запятых — так и
  оставь. Замена только искажённого слова, иначе пользователь перестанет доверять
  прочтениям.
- Не исправлять незнакомые имена собственные на знакомые: «Ванневар» — не
  опечатка в «Ван Гог». Если имя встречалось в контексте — оно правильное.
- Не звать внешние спеллчекеры/модели для этой задачи.
- Не отвечать и **не вызывать инструменты** до того, как показал прочтение
  (шаг 4). Проверка перед первым действием в ходе: «я поменял какое-то слово в
  голове? — тогда где строка „Понял как“?»
